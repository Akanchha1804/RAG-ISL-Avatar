## 1. Introduction

### 1.1 Purpose
This document specifies the functional and non-functional requirements for the
RAG-Augmented Speech-to-ISL Avatar Generator — a system that converts spoken or
typed English/Hindi sentences into Indian Sign Language (ISL) gloss sequences
and renders them as animated signs on a 3D avatar, using Retrieval-Augmented
Generation (RAG) to improve translation quality under limited ISL training data.

### 1.2 Scope
The system accepts speech or text input, retrieves similar sentence-gloss
examples from an ISL knowledge base, generates an ISL gloss sequence using a
fine-tuned sequence-to-sequence model, and animates a rigged 3D avatar to
perform the corresponding signs in near real time.

In scope:
- Speech-to-text transcription (English/Hindi)
- RAG-based retrieval of similar sentence-gloss pairs
- Gloss sequence generation (fine-tuned transformer)
- Gloss-to-animation mapping and clip blending
- Web-based demo interface

Out of scope (deferred to Future Enhancements):
- Facial expressions / non-manual markers (grammar-bearing expressions)
- Finger spelling for out-of-vocabulary words
- Full sentence-level ISL grammar beyond topic-comment reordering
- Mobile native application

### 1.3 Intended Audience
Project evaluators, project guide/mentor, and the developer (solo B.Tech
final-year student) for planning, implementation tracking, and viva defense.

### 1.4 Definitions, Acronyms, Abbreviations
| Term | Meaning |
|---|---|
| ISL | Indian Sign Language |
| Gloss | Written representation of signs, typically in capitalized root-word form |
| RAG | Retrieval-Augmented Generation |
| STT | Speech-to-Text |
| FAISS | Facebook AI Similarity Search (vector index library) |
| MCP | Model Context Protocol |
| Non-manual markers | Facial/body grammar cues in sign languages (e.g., eyebrow raise for questions) |

## 2. Overall Description

### 2.1 Product Perspective
Standalone accessibility application; not a replacement for certified human
ISL interpreters. Positioned as an assistive communication aid and a research
demonstration of RAG applied to sign language production — a gap not
addressed in prior ISL or general sign-language-production literature.

### 2.2 User Classes
| User Class | Description |
|---|---|
| Primary user (hearing person) | Speaks/types a sentence to be signed to a Deaf/HoH person |
| Evaluator/Viewer (Deaf/HoH person) | Watches the avatar output |
| Developer/Admin | Manages the ISL knowledge base, retrains models, monitors system |

### 2.3 Operating Environment
- Backend: Python 3.11+, FastAPI, runs on a single GPU-enabled machine (dev) / containerized deployment (Docker)
- Frontend: React + Tailwind CSS, modern browser (Chrome/Edge/Firefox, WebGL-capable for avatar rendering)
- Avatar rendering: Unity WebGL build or Three.js, depending on final integration choice

### 2.4 Assumptions and Dependencies
- ISL-CSLTR and CISLR datasets are available and sufficient for fine-tuning and retrieval corpus construction
- A pre-built or sourced rigged 3D avatar with a base ISL sign clip library is available or built during the project
- Real-time performance is "near real-time" (sub-few-second latency), not broadcast-grade live captioning speed
- Single-user demo scale; not designed for concurrent high-traffic production load

## 3. Functional Requirements

### FR-1: Speech/Text Input
- FR-1.1: System shall accept typed text input via a web form.
- FR-1.2: System shall accept microphone speech input and transcribe it using Distil-Whisper.
- FR-1.3: System shall support English input at minimum; Hindi support is a stretch goal.

### FR-2: RAG Retrieval
- FR-2.1: System shall embed the input sentence using a sentence-transformer model (MiniLM).
- FR-2.2: System shall retrieve the top-k (configurable, default 3–5) most similar sentence-gloss pairs from a FAISS vector index built over the ISL-CSLTR and CISLR corpora.
- FR-2.3: Retrieved examples shall be passed as contextual few-shot examples to the gloss generation model.

### FR-3: Gloss Generation
- FR-3.1: System shall generate an ISL gloss sequence from the input sentence and retrieved examples using a fine-tuned transformer (Flan-T5/mT5).
- FR-3.2: The gloss generator shall apply learned ISL-specific reordering (e.g., topic-comment structure) rather than word-for-word English substitution.
- FR-3.3: System shall log the generated gloss sequence for evaluation/debugging.

### FR-4: Animation Mapping
- FR-4.1: System shall map each gloss token to a corresponding pre-built animation clip.
- FR-4.2: System shall blend transitions between consecutive sign clips to reduce visual jerkiness (co-articulation handling).
- FR-4.3: System shall play the resulting animation sequence on a rigged 3D avatar in the frontend.
- FR-4.4: System shall handle unknown/out-of-vocabulary gloss tokens gracefully (e.g., skip with a logged warning; finger-spelling fallback is a future enhancement).

### FR-5: MCP Integration (optional/stretch)
- FR-5.1: System shall optionally expose a `translate_to_isl(text)` tool via an MCP server wrapper for integration with external applications.

### FR-6: Admin/Evaluation Functions
- FR-6.1: System shall support an ablation mode comparing gloss output with RAG enabled vs. disabled, for evaluation reporting.
- FR-6.2: System shall allow the ISL knowledge base (retrieval corpus) to be updated without retraining the generation model.

## 4. Non-Functional Requirements

| ID | Requirement | Target |
|---|---|---|
| NFR-1 | Latency (text input → animation start) | < 3–5 seconds on dev hardware |
| NFR-2 | STT accuracy | Word Error Rate comparable to published Distil-Whisper benchmarks on clean audio |
| NFR-3 | Gloss generation quality | Measured via BLEU/ROUGE against held-out ISL-CSLTR/CISLR gloss references, plus qualitative review |
| NFR-4 | Usability | No ISL/technical expertise required to operate the input interface |
| NFR-5 | Portability | Containerized via Docker for reproducible setup |
| NFR-6 | Maintainability | Modular pipeline stages (STT / retrieval / generation / animation) independently replaceable |
| NFR-7 | Data privacy | No persistent storage of user speech/audio beyond the current session unless explicitly opted in |

---

## 5. External Interface Requirements

- **User Interface:** Web page with microphone/text input, live status indicator (transcribing → retrieving → generating → animating), avatar viewport
- **APIs:** Internal REST/WebSocket API between frontend and backend (see API Specification document)
- **Hardware:** Standard webcam-optional, microphone-required for speech input; GPU recommended for training/inference speed, not strictly required for CPU-based inference of small models

---

## 6. Constraints
- Solo-developer, single-semester timeline
- No large-scale ISL motion-capture data available — must rely on ISL-CSLTR- and CISLR-scale corpora and existing/sourced animation clip libraries
- Must include a genuine ML component (per project requirement) — satisfied by the fine-tuned gloss generator
- Real-time performance bounded by retrieval + generation + animation pipeline latency

## 7. Future Enhancements (Out of Scope for v1)
- Facial expression / non-manual marker generation
- Finger-spelling fallback for OOV words
- Hindi-first support
- Browser extension / video-call integration
- Mobile application
- Expanded ISL vocabulary and animation clip library
